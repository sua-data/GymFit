웹캠 기반 실시간 자세 분석과 개인·PT 회원 운동 관리를 제공하는 AI 헬스케어 서비스

프로젝트 상태

개인 프로젝트로 기획부터 UI/UX 설계, 백엔드, 데이터베이스, AI 자세 분석, 테스트, Docker 기반 배포까지 구현했습니다.스쿼트·푸시업·숄더프레스 실시간 자세 코칭과 운동 기록, PT 숙제·피드백·일정, 역할별 권한 관리 기능을 제공합니다.자동 테스트 기준 163 passed를 확인했으며, Docker / Docker Compose + AWS 환경 배포까지 완료했습니다.

1. 프로젝트 소개

GYMFIT은 개인 운동자, PT 회원, 트레이너를 하나의 서비스 안에서 연결하는 웹 기반 운동 관리 서비스입니다.

웹캠 영상에서 YOLO11 Pose로 사용자의 관절 좌표를 추출하고 운동별 관절 각도와 동작 상태를 분석하여 다음 정보를 실시간으로 제공합니다.

반복 횟수

세트 진행 상태

운동 시간

자세 점수

자세 피드백

베스트 자세 이미지

운동이 종료되면 반복 횟수, 완료 세트, 운동 시간, 예상 소모 칼로리, 자세 점수와 피드백을 운동 기록으로 저장합니다.

PT 회원의 운동 기록과 자세 분석 결과는 담당 트레이너가 확인할 수 있으며, 트레이너는 PT 숙제·피드백·일정을 관리할 수 있습니다.

2. 기획 배경

개인 운동자는 혼자 운동할 때 자신의 자세가 올바른지 실시간으로 판단하기 어렵습니다.

또한 운동 루틴, 운동 기록, PT 숙제와 피드백이 여러 서비스나 화면에 분산되면 지속적인 운동 관리가 어렵습니다.

GYMFIT은 다음 문제를 해결하기 위해 기획했습니다.

개인 운동자의 자세 확인 어려움

운동 루틴과 기록 관리의 분산

PT 수업이 없는 날의 피드백 공백

트레이너의 회원별 운동 데이터 관리 부담

7. 서비스 차별점

개인 + PT 통합 구조

개인 운동자, PT 회원, 트레이너가 하나의 서비스 안에서 연결됩니다.

AI 자세 코칭

트레이너가 없는 환경에서도 웹캠 기반 자세 분석과 반복 횟수 자동 카운트를 제공합니다.

운동 데이터 통합 관리

루틴, 운동 기록, 자세 분석 결과, PT 숙제, 피드백, 일정을 한 서비스에서 관리합니다.

트레이너 데이터 공유

PT 회원의 운동 기록과 자세 분석 결과를 담당 트레이너가 확인하고 피드백할 수 있습니다.

역할 및 관계 기반 접근 제어

역할뿐 아니라 트레이너 승인 상태, 재직 상태, 활성 PT 관계를 함께 검증합니다.

개인정보 최소 저장

운동 전체 영상이 아닌 운동 결과와 베스트 자세 이미지 중심으로 저장합니다.

18. 개발 중 해결한 문제

18.1 프레임 단위 운동 상태 흔들림

단일 프레임의 각도 변화만으로 상태가 변경되지 않도록 연속 프레임 기반 상태 안정화 로직을 적용했습니다.

18.2 빠른 동작에서의 카운트 누락

푸시업 등 빠른 운동에서 관절 탐지가 순간적으로 누락되는 문제를 고려해 운동별 상태 판정 로직과 허용 프레임 조건을 조정했습니다.

18.3 운동별 분석 로직 결합 문제

초기에는 하나의 분석 흐름에 운동 조건이 섞일 가능성이 있어 운동별 분석기를 분리하고 Factory 방식으로 생성하도록 변경했습니다.

18.4 숄더프레스 좌우 팔 전환 문제

좌우 팔 신뢰도에 따라 분석 측면이 변경될 때 기존 상태 후보가 남아 잘못된 카운트가 발생할 수 있어 측면 전환 시 후보 상태와 연속 프레임 값을 초기화했습니다.

18.5 운동시간 과다 계산

코칭 화면을 오래 열어 둔 경우 실제 운동을 하지 않아도 운동 시간이 증가하는 문제를 해결하기 위해 관절 변화, stage 변화, count 증가를 기준으로 활동시간만 누적하도록 수정했습니다.

18.6 운동 기록과 루틴 상태 불일치

운동 기록 저장과 운동 계획 / PT 숙제 상태 갱신을 하나의 흐름으로 연결하고 유일성 검증을 적용했습니다.

18.7 PT 일정 중복

회원 또는 트레이너의 일정이 겹치지 않도록 중복 검증 로직을 적용했습니다.

18.8 사용자 역할별 데이터 접근

프론트 메뉴 제한만으로는 직접 API 호출을 막을 수 없어 백엔드에서 역할, 승인, 재직, 활성 PT 관계를 공통 검증하도록 구성했습니다.

18.9 대시보드 운동시간 표시 오류

운동 기록에는 시간이 저장되어 있었지만 최근 운동 API 응답에서 workout_minutes가 누락되어 운동시간 미입력으로 표시되는 문제가 있었습니다.

API 응답에 실제 운동 시간을 포함하도록 수정하고, 값이 0 / null / undefined인 경우에만 미입력 상태로 처리했습니다.

18.10 개발 환경 차이

개발 PC 간 Python / MariaDB 환경 차이를 줄이기 위해 .env, requirements.txt, DB dump와 Docker 환경을 분리하여 관리했습니다.
