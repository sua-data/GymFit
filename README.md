# GYMFIT

웹캠 기반 실시간 자세 분석과 운동 기록 관리를 제공하는 AI 헬스케어 서비스

> **프로젝트 상태**  
> 회원, 운동 루틴, 운동 기록, PT 관리 및 YOLO Pose 기반 자세 분석 기능을 구현했습니다.  
> 현재 모바일 카메라 환경에서의 자세 인식률과 운동 카운트 정확도는 추가 검증이 필요한 상태입니다.

---

## 1. 프로젝트 소개

GYMFIT은 개인 운동자, PT 회원, 트레이너를 위한 웹 기반 운동 관리 서비스입니다.

웹캠 영상에서 사용자의 관절 좌표를 추출하고 운동 자세와 동작 단계를 분석하여 반복 횟수, 세트 진행 상태, 자세 점수와 피드백을 제공합니다.

운동이 종료되면 수행 시간, 반복 횟수, 완료 세트, 예상 소모 칼로리, 자세 점수와 베스트 자세 이미지를 운동 기록으로 저장합니다.

또한 PT 회원이 수행한 운동 루틴, 운동 기록과 자세 분석 결과를 담당 트레이너가 확인하고 피드백할 수 있는 통합 운동 관리 구조를 구현했습니다.

---

## 2. 기획 배경

개인 운동자는 혼자 운동할 때 자신의 자세가 올바른지 실시간으로 판단하기 어렵습니다.

운동 루틴과 운동 기록이 여러 화면이나 서비스에 분산되어 관리되는 경우가 많으며, PT 회원은 수업이 없는 날에는 자세 피드백을 받기 어렵습니다.

트레이너 역시 여러 회원의 운동 수행 상태, 숙제, 일정과 변화 과정을 체계적으로 관리할 수 있는 도구가 필요합니다.

GYMFIT은 다음 문제를 해결하기 위해 기획했습니다.

- 개인 운동자의 자세 확인 어려움
- 운동 루틴과 기록 관리의 분산
- PT 수업이 없는 날의 피드백 공백
- 트레이너의 회원별 운동 데이터 관리 부담

## 5. AI 자세 분석 방식

현재 스쿼트, 푸시업, 숄더프레스 운동의 자세 분석 로직을 구성했습니다.

운동별 분석기를 분리하여 각 운동에 필요한 관절 좌표와 각도 기준을 적용하도록 구현했습니다.

스쿼트는 무릎 각도, 동작 깊이와 상체 기울기를 중심으로 상태를 판정하며, 푸시업과 숄더프레스는 운동별 관절 각도와 자세 조건을 기준으로 분석합니다.

다만 실제 모바일 카메라 환경에서의 인식률과 카운트 정확도는 추가 검증이 필요한 상태입니다.

### 5.1 지원 운동

- 스쿼트
- 푸시업
- 숄더프레스

### 5.2 공통 분석 과정

1. 웹캠에서 실시간 영상 프레임을 입력합니다.
2. YOLO11 Pose 모델로 사람과 관절 좌표를 탐지합니다.
3. 관절별 confidence와 사람 Bounding Box 크기를 검증합니다.
4. 운동별로 필요한 관절 좌표를 선택합니다.
5. 관절 좌표를 이용해 운동별 각도를 계산합니다.
6. 계산된 각도와 자세 조건에 따라 운동 상태를 판정합니다.
7. 동일 상태가 일정 프레임 이상 유지되면 상태를 확정합니다.
8. 내려간 상태와 올라온 상태의 전환을 기준으로 반복 횟수를 증가시킵니다.
9. 목표 반복 횟수를 달성하면 다음 세트로 진행합니다.
10. 운동 종료 시 수행 결과를 데이터베이스에 저장합니다.

### 5.3 스쿼트 판정 기준

- 내려간 상태: 무릎 각도 약 110도 이하
- 올라온 상태: 무릎 각도 약 155도 이상
- 깊은 스쿼트 기준: 약 100도
- 자세 안내 기준: 약 135도
- 최소 관절 신뢰도: 0.35
- 최소 사람 탐지 크기: 약 70 × 150
- 상태 확정 프레임: 3프레임
- 최대 관절 누락 허용: 15프레임

프레임별 탐지 오차로 운동 상태가 흔들리는 문제를 줄이기 위해 동일한 상태가 일정 프레임 이상 유지된 경우에만 운동 상태를 변경하도록 구현했습니다.

## 6. 서비스 차별점

### 개인 운동자와 PT 회원 통합

개인 운동자, PT 회원과 트레이너가 하나의 서비스 안에서 연결되는 구조를 구현했습니다.

### AI 자세 코칭

트레이너가 없는 환경에서도 웹캠을 통해 운동 자세, 반복 횟수와 실시간 피드백을 확인할 수 있도록 구성했습니다.

### 운동 데이터 통합 관리

운동 루틴, 운동 기록, 자세 분석 결과, PT 숙제, 트레이너 피드백과 PT 일정을 하나의 서비스에서 관리합니다.

### 트레이너 데이터 공유

PT 회원이 수행한 운동 기록과 자세 분석 결과를 담당 트레이너가 확인하고 피드백할 수 있도록 설계했습니다.

### 역할 및 관계 기반 접근 제어

단순 사용자 역할 확인뿐만 아니라 트레이너 승인 상태, 재직 상태와 활성 PT 관계를 검증하여 데이터 접근 범위를 제한했습니다.

### 개인정보 최소 저장

전체 운동 영상보다 운동 결과와 베스트 자세 이미지 중심으로 저장하여 개인정보 저장 범위를 줄였습니다.

| 알림 | 사용자별 알림 내용과 읽음 상태 |

주요 테이블은 사용자 계정, 운동 계획, 운동 기록, PT 관리 데이터가 서로 연결되는 구조로 설계했습니다.

운동 계획은 기본 운동 또는 사용자가 직접 등록한 운동을 참조할 수 있으며, 운동 기록은 운동 계획이나 PT 숙제와 연결될 수 있도록 구성했습니다.

PT 관련 데이터는 회원과 트레이너의 관계 상태를 기준으로 접근 권한을 검증합니다.

## 14. 개발 중 해결한 문제

### 14.1 잘못된 운동 카운트 증가

사람 이외의 객체 또는 신뢰도가 낮은 관절 좌표가 운동 동작으로 처리되어 카운트가 증가하는 문제가 있었습니다.

사람 탐지 결과만 처리하고 관절 신뢰도, 사람 Bounding Box 크기와 관절 누락 허용 프레임 조건을 추가하여 잘못된 카운트를 줄였습니다.

### 14.2 프레임 단위 상태 흔들림

한 프레임의 각도 변화만으로 `UP`, `DOWN` 상태가 반복해서 변경되는 문제가 있었습니다.

동일한 상태가 일정 프레임 이상 유지된 경우에만 운동 상태를 확정하도록 상태 안정화 로직을 적용했습니다.

### 14.3 실시간 카운트와 세트 상태 불일치

운동 상태와 세트 완료 메시지는 변경되지만 화면의 실시간 카운트가 즉시 반영되지 않는 문제가 있었습니다.

운동 분석 결과와 화면 상태 업데이트 흐름을 분리하고 현재 반복 횟수와 세트 정보를 주기적으로 갱신하도록 수정했습니다.

### 14.4 Google 로그인 시간 오류

Google ID Token 검증 과정에서 `Token used too early` 오류가 발생했습니다.

PC 시스템 시간을 인터넷 시간과 동기화하여 토큰 발급 시간과 서버 시간 차이를 해결했습니다.

### 14.5 운동 루틴 참조 구조 개선

초기 운동 계획은 기본 운동 테이블만 참조하여 사용자가 직접 등록한 운동을 저장하기 어려운 구조였습니다.

사용자 운동 테이블을 추가하고 운동 계획이 기본 운동 또는 사용자 운동 중 하나를 참조할 수 있도록 데이터베이스 구조를 개선했습니다.

### 14.6 운동 기록과 관련 상태 불일치

운동 기록 저장 후 연결된 운동 계획 또는 PT 숙제 상태가 함께 변경되지 않거나, 하나의 운동 기록이 여러 숙제와 연결될 가능성이 있었습니다.

운동 기록 저장과 관련 상태 변경을 하나의 트랜잭션으로 처리하고 운동 기록과 PT 숙제 연결에 유일성 검증을 추가했습니다.

운동 기록을 삭제한 경우에는 연결된 PT 숙제의 완료 상태도 적절한 진행 상태로 복원하도록 처리했습니다.

### 14.7 PT 일정 중복 등록

동일 회원이나 트레이너에게 서로 겹치는 PT 일정이 동시에 등록될 수 있는 문제가 있었습니다.

일정 등록 과정에서 사용자와 PT 관계 데이터를 잠그고 겹치는 예정 일정을 다시 검사하여 중복 등록을 방지했습니다.

### 14.8 PT 숙제 운동 검색 권한 오류

트레이너가 PT 숙제를 등록할 때 회원 전용 운동 검색 API를 호출하여 `403 Forbidden` 오류가 발생했습니다.

트레이너가 담당 회원의 기본 운동과 사용자 등록 운동을 조회할 수 있는 PT 숙제 전용 운동 검색 API를 분리하여 해결했습니다.

### 14.9 사용자 역할별 접근 제어

프론트 화면에서만 메뉴를 숨길 경우 API 주소를 직접 호출하여 다른 사용자의 데이터에 접근할 수 있는 문제가 있었습니다.

사용자 역할, 트레이너 승인 상태, 재직 상태와 활성 PT 관계를 백엔드에서 공통 검증하도록 접근 제어 로직을 분리했습니다.

담당 회원의 데이터만 접근할 수 있도록 회원과 트레이너 관계를 추가로 검증했습니다.

### 14.10 인증 처리 방식 통일

화면마다 인증 오류를 처리하는 방식이 달라 로그인 만료 또는 권한 오류에 일관되게 대응하기 어려웠습니다.

공통 API 클라이언트를 구성하여 인증 헤더를 자동으로 추가하고 `401`, `403` 응답을 공통으로 처리하도록 수정했습니다.

### 14.11 여러 개발 기기 간 환경 차이

데스크톱과 노트북의 Python 및 MariaDB 버전 차이로 실행 환경이 달라지는 문제가 있었습니다.

가상환경, `requirements.txt`, 데이터베이스 덤프 파일과 환경변수 파일을 분리하여 개발 환경을 재구성했습니다.

### 14.12 모바일 실기기 화면 테스트

Chrome 개발자 도구에서 모바일 화면 크기를 반복해서 설정해야 하는 불편함이 있었습니다.

FastAPI 서버를 `0.0.0.0`으로 실행하고 Tailscale을 이용하여 모바일 기기에서 실제 화면 크기로 접속할 수 있도록 구성했습니다.

다만 모바일 브라우저의 카메라 사용은 HTTP 보안 정책의 영향을 받을 수 있어 HTTPS 환경에서 추가 검증이 필요합니다.

## 15. 테스트 및 제한 사항

일반 웹 기능, 데이터베이스 연동, 사용자 역할별 기능과 API 접근 제어는 로컬 환경에서 기능별 테스트를 진행했습니다.

AI 자세 코칭 기능은 다음 흐름까지 구현했습니다.

- YOLO Pose 모델 로드
- 웹캠 프레임 입력
- 사람 및 관절 좌표 추출
- 관절 신뢰도 검증
- 관절 각도 계산
- 운동 상태 판정
- 반복 횟수 및 세트 계산
- 자세 점수와 피드백 생성
- 베스트 자세 이미지 선택
- 운동 결과 저장

다만 현재 카메라 테스트 환경의 제약으로 인해 다음 항목은 추가 검증이 필요합니다.

- 실제 운동 환경에서의 반복 횟수 정확도
- 사용자와 카메라 거리 변화에 따른 인식률
- 촬영 각도에 따른 관절 탐지 안정성
- 조명 변화에 따른 관절 좌표 정확도
- 모바일 브라우저별 카메라 권한 처리
- 모바일 카메라 해상도와 프레임 처리 성능
- 스쿼트, 푸시업, 숄더프레스별 판정 임계값의 실사용 적합성

따라서 현재 AI 자세 분석 기능은 구현된 상태이며, 실환경 정확도 검증과 임계값 보정은 후속 개선 과제로 관리하고 있습니다.
