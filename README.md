# GYMFIT

웹캠 기반 실시간 자세 분석과 운동 기록 관리를 제공하는 AI 헬스케어 서비스

---

## 1. 프로젝트 소개

GYMFIT은 개인 운동자, PT 회원, 트레이너를 위한 웹 기반 운동 관리 서비스입니다.

웹캠으로 사용자의 운동 자세를 실시간 분석하고 운동 횟수와 세트를 자동으로 측정합니다. 운동 종료 후에는 운동 기록, 자세 점수, 피드백을 저장하여 사용자가 자신의 운동 변화를 확인할 수 있도록 설계했습니다.

또한 PT 회원의 운동 루틴, 운동 기록, 자세 분석 결과를 담당 트레이너가 확인하고 관리할 수 있는 통합 운동 관리 구조를 목표로 합니다.

---

## 2. 기획 배경

개인 운동자는 자신의 자세가 올바른지 스스로 판단하기 어렵고, 운동 루틴과 운동 기록도 여러 서비스에 분산되어 관리되는 경우가 많습니다.

PT 회원은 수업이 없는 날에는 자세 피드백을 받기 어렵고, 트레이너는 여러 회원의 운동 수행 상태와 변화 과정을 체계적으로 관리할 수 있는 도구가 필요합니다.

GYMFIT은 다음 문제를 해결하기 위해 기획했습니다.

- 개인 운동자의 자세 확인 어려움
- 운동 루틴과 기록 관리의 분산
- PT 수업이 없는 날의 피드백 공백
- 트레이너의 회원별 운동 데이터 관리 부담

## 5. AI 자세 분석 방식

현재 스쿼트 운동을 중심으로 실시간 자세 분석 기능을 구현했습니다.

### 분석 과정

1. 웹캠으로 실시간 영상 프레임을 입력합니다.
2. YOLO Pose 모델로 사람과 관절 좌표를 탐지합니다.
3. 엉덩이, 무릎, 발목 좌표를 이용해 무릎 각도를 계산합니다.
4. 관절 각도에 따라 `UP`, `DOWN` 상태를 판정합니다.
5. 사용자가 내려갔다가 다시 올라오면 스쿼트 횟수를 증가시킵니다.
6. 스쿼트 깊이와 상체 기울기를 분석하여 실시간 피드백을 제공합니다.
7. 목표 횟수를 달성하면 다음 세트로 진행합니다.
8. 운동 종료 시 수행 결과를 데이터베이스에 저장합니다.

### 스쿼트 판정 기준

- 내려간 상태: 무릎 각도 약 110도 이하
- 올라온 상태: 무릎 각도 약 155도 이상
- 깊은 스쿼트 기준: 약 100도
- 자세 안내 기준: 약 135도
- 최소 관절 신뢰도: 0.35
- 최소 사람 탐지 크기: 약 70 × 150
- 상태 확정 프레임: 3프레임
- 최대 관절 누락 허용: 15프레임

프레임별 탐지 오차로 운동 상태가 흔들리는 문제를 줄이기 위해 동일한 상태가 일정 프레임 이상 유지된 경우에만 동작 상태를 변경하도록 구현했습니다.

## 6. 서비스 차별점

### 개인 운동자와 PT 회원 통합

개인 운동자, PT 회원, 트레이너가 하나의 서비스 안에서 연결되는 구조를 지향합니다.

### AI 자세 코칭

트레이너가 없는 환경에서도 웹캠을 통해 실시간 운동 자세 피드백을 제공합니다.

### 운동 데이터 통합 관리

운동 루틴, 운동 기록, 자세 분석 결과, PT 일정과 수업일지를 하나의 서비스에서 관리합니다.

### 트레이너 데이터 공유

PT 회원이 수행한 운동과 자세 분석 결과를 담당 트레이너가 확인할 수 있도록 설계했습니다.

### 개인정보 최소 저장

전체 운동 영상보다는 운동 결과와 베스트 자세 이미지 중심으로 저장하여 개인정보 저장 범위를 줄였습니다.

## 11. 실행 방법

### 11.1 프로젝트 복제

```bash
git clone https://github.com/sua-data/GymFit.git
cd GymFit
```

### 11.2 가상환경 생성

```bash
python -m venv .venv
```

### 11.3 가상환경 활성화

Windows PowerShell:

```powershell
.venv\Scripts\activate
```

PowerShell 실행 정책 오류가 발생하는 경우:

```powershell
Set-ExecutionPolicy -Scope Process -ExecutionPolicy Bypass
.venv\Scripts\activate
```

### 11.4 패키지 설치

```bash
pip install -r requirements.txt
```

### 11.5 환경변수 설정

프로젝트 루트에 `.env` 파일을 생성합니다.

```env
DB_HOST=localhost
DB_PORT=3306
DB_USER=root
DB_PASSWORD=your_password
DB_NAME=gymfit
```

Google 로그인을 사용하는 경우 Google Client ID와 인증 관련 환경변수를 추가해야 합니다.

### 11.6 데이터베이스 생성

MariaDB에서 `gymfit` 데이터베이스를 생성합니다.

```sql
CREATE DATABASE gymfit
CHARACTER SET utf8mb4
COLLATE utf8mb4_unicode_ci;
```

필요한 초기 SQL 또는 마이그레이션 SQL을 실행합니다.

### 11.7 서버 실행

```bash
uvicorn backend.main:app --reload
```

브라우저 접속 주소:

```text
http://127.0.0.1:8000
```

외부 기기에서 접속할 수 있도록 실행하는 경우:

```bash
uvicorn backend.main:app --host 0.0.0.0 --port 8000 --reload
```

같은 네트워크 또는 Tailscale에 연결된 모바일 기기에서 다음 주소로 접속합니다.

```text
http://PC_IP_ADDRESS:8000
```

## 14. 개발 중 해결한 문제

### 14.1 잘못된 운동 카운트 증가

사람 이외의 객체나 신뢰도가 낮은 관절 좌표가 운동 동작으로 인식되어 카운트가 증가하는 문제가 있었습니다.

사람 탐지 결과만 처리하고 관절 신뢰도, 사람 박스 크기, 관절 누락 허용 프레임 조건을 추가하여 잘못된 카운트를 줄였습니다.

### 14.2 프레임 단위 상태 흔들림

한 프레임의 각도 변화만으로 `UP`, `DOWN` 상태가 반복해서 변경되는 문제가 있었습니다.

동일한 상태가 일정 프레임 이상 유지된 경우에만 운동 상태를 확정하도록 안정화 로직을 적용했습니다.

### 14.3 실시간 카운트와 세트 상태 불일치

운동 상태와 세트 완료 메시지는 변경되지만 화면의 실시간 카운트가 즉시 반영되지 않는 문제가 있었습니다.

운동 분석 결과와 화면 상태 업데이트 흐름을 분리하고, 현재 반복 횟수와 세트 정보를 주기적으로 갱신하도록 수정했습니다.

### 14.4 Google 로그인 시간 오류

Google ID Token 검증 과정에서 `Token used too early` 오류가 발생했습니다.

PC 시스템 시간을 인터넷 시간과 동기화하여 토큰 발급 시간과 서버 시간 차이를 해결했습니다.

### 14.5 운동 루틴 참조 구조 개선

초기 운동 계획은 기본 운동 테이블만 참조하여 사용자가 직접 등록한 운동을 저장하기 어려운 구조였습니다.

`user_exercise` 테이블을 추가하고 `workout_plan`이 기본 운동 또는 사용자 운동 중 하나를 참조할 수 있도록 데이터베이스 구조를 개선했습니다.

### 14.6 여러 개발 기기 간 환경 차이

데스크톱과 노트북의 Python 및 MariaDB 버전 차이로 실행 환경이 달라지는 문제가 있었습니다.

가상환경, `requirements.txt`, 데이터베이스 덤프 파일, 환경변수 파일을 분리하여 개발 환경을 재구성했습니다.

### 14.7 모바일 실기기 테스트

Chrome 개발자 도구에서 모바일 화면을 반복해서 설정해야 하는 불편함이 있었습니다.

FastAPI 서버를 `0.0.0.0`으로 실행하고 Tailscale을 이용해 모바일 기기에서 실제 화면 크기로 테스트할 수 있도록 구성했습니다.
